kzk-harness 스킬 & 워크플로우 지도

Claude Code 위에 올라가는 18개 마크다운 스킬이 어떻게 서로 호출되고, 어디에서 어떻게 로드되는지 한 페이지로 정리.
18 skills active 8 hooks (project + global) harness-share.md §1–§33 SoT

이 문서는 두 부류의 독자를 동시에 노립니다. ① 처음 보는 사람은 "이 라이브러리가 뭐고, 어떤 키워드 한 마디가 어떤 자동화를 트리거하는지" 5분 안에 감 잡는 게 목표. ② 메인테이너 (나)는 cycle 진행 중 "지금 어디 흐름에 있더라, 이 스킬이 누구 부르더라" 빠르게 참조하는 게 목표.

스킬 본문은 각 skills/kzk-*/SKILL.md 가 SoT 이고, 가로지르는 룰은 harness-share.md (§1–§33) 가 SoT. 이 HTML 은 그 둘에서 파생된 읽기 전용 인덱스 입니다 — SoT 가 바뀌면 §10 의 hook 이 commit 을 차단해서 동기화를 강제합니다.

2. 멘탈 모델

Claude Code 는 본인 (메인 에이전트) + Skill (markdown) + Subagent (전문 에이전트) + Hook (스크립트) + MCP (외부 도구 서버) 의 다섯 가지로 동작합니다. kzk-harness 는 그 중 Skill 18개 + Hook 8개를 한 묶음으로 얹는 워크플로우 레이어입니다. 신규 capability 가 아니라, 기존 capability 를 안전하고 일관되게 부르도록 규율(discipline)을 추가합니다.

Skillmarkdown
트리거 키워드가 prompt 에 등장하면 본문이 메인 컨텍스트로 자동 로드. 코드 X, 마크다운 본문이 그대로 룰북.

kzk-* 18개 모두 이 형태

  • 위치: ~/.claude/skills/kzk-*/SKILL.md (global) 또는 .claude/skills/kzk-*/SKILL.md (project-only)
  • 인스톨: install/install-global.sh 또는 README 의 PROJECT-ONLY 절차
Subagentruntime
메인이 Agent({ subagent_type: '...', ... }) 로 위임. 별도 context 창 + 별도 model.

이 레포가 의존하는 subagent

  • oh-my-claudecode:explore — read-heavy 탐색 (sonnet)
  • oh-my-claudecode:executor — 코드 작성 (sonnet/opus)
  • oh-my-claudecode:critic — 리뷰 / 검증 (opus)
  • oh-my-claudecode:verifier — 완료 검증 (fresh agent)
Hooknode mjs
PreToolUse / PostToolUse / UserPromptSubmit / Stop 이벤트에 묶이는 stdin-driven 스크립트. JSON 입출력으로 메인을 가로채거나 system-reminder 주입.

kzk-harness 의 8개

  • install/hooks/keyword-detector.mjs 등 — 글로벌 install 시 ~/.claude/skills/.kzk-harness-shared/hooks/ 로 복제 + ~/.claude/settings.json 에 등록
  • 이 레포 전용: .claude/hooks/check-skill-flow-fresh.mjs (§10)
MCP servertool
메인이 호출 가능한 외부 tool 서버. Skill 내부에서 mcp__plugin_context7_context7__query-docs 같은 이름으로 호출.

이 레포가 권장하는 MCP

  • context7 — 외부 라이브러리 API 문서 (kzk-codebase-survey Step 4 에서 사용)
  • code-review-graph — Tree-sitter + SQLite 코드 그래프 (kzk-codebase-survey Step 0.5/1/2)
  • playwright-mcp — 브라우저 자동화 (kzk-playwright-verification Gate 4, kzk-web-loop)

3. 외부 스킬 & 도구가 어디서 어떻게 로드되나

이 레포의 kzk-* 스킬은 다른 플러그인 / MCP 서버 / CLI 도구를 적극 활용합니다. "어느 파일 / 어느 명령이 그것을 메인 세션에 끌어오는지" 한 표에 정리:

구성요소역할로드 위치 / 방식사용처 (kzk-*)
kzk-* 18개 이 레포의 본체 Global: ~/.claude/skills/kzk-*/SKILL.md (README install one-liner → install/install-global.sh --enable-hooks --regression-recall --fix-scope-trigger --freshness-guard).
Project-only: .claude/skills/kzk-*/SKILL.md (README PROJECT-ONLY 절차). 		전부
harness-share.md 가로지르는 SoT (§1–§33) Global 설치 시 ~/.claude/skills/.kzk-harness-shared/harness-share.md 로 복제 (dot-prefix → invocable skill 아님).
Project-only 시 repo root harness-share.md 로 복제.
개발 모드 (--symlink-mode) 는 이 파일만 symlink. 		전부 — 각 SKILL.md 의 "Authoritative source" 라인에서 참조
~/.claude/CLAUDE.md 마커 블록 글로벌 스킬 라우팅 표 install-global.sh 가 <!-- kzk-harness:START --> 마커 블록을 idempotent 하게 갈아치움 (블록 바깥은 byte-for-byte 보존). 키워드 → 스킬 매핑 표
oh-my-claudecode (OMC) 플러그인 subagent / deepinit / ToolSearch 헬퍼 Claude Code 세션 안에서 /plugin 명령으로 설치. 감지: ~/.claude/plugins/installed_plugins.json 에서 oh-my-claudecode@* key 존재 여부.
미설치 시 install/dependencies.sh 가 /plugin 안내 출력 (절대 하드 페일 X). 		large-task-delegation, pre-commit-gate (Gate 0 deepinit_manifest), spec-and-review (critic fallback), pre-merge-sync (deepinit), test-coverage (verifier)
playwright-mcp 브라우저 자동화 MCP 세션 안에서 /plugin 또는 claude mcp add playwright -- npx -y @playwright/mcp@latest.
감지: ~/.claude.json + <project>/.mcp.json 의 "playwright" + @playwright/mcp 항목. 		playwright-verification (Gate 4), web-loop
gstack 플러그인 /learn JSONL 저장소 세션 /plugin 설치. 감지: ~/.gstack/projects/ 디렉토리 존재. regression-memory (recall hook), web-loop (cycle 회고)
context7 MCP 외부 lib 문서 fetch 플러그인 또는 .mcp.json 등록 (이미 OMC 와 함께 자주 묶여 있음). 호출명: mcp__plugin_context7_context7__resolve-library-id, ...__query-docs. codebase-survey Step 4
code-review-graph (CRG) Tree-sitter + SQLite 코드 그래프 install/dependencies.sh 가 pip --user → pipx fallback 으로 자동 설치 후 code-review-graph install 호출 → 프로젝트 안에 .mcp.json 자동 등록 (MCP 서버로 self-register). CLI 로도 사용 가능.
그래프 빌드는 프로젝트별: code-review-graph build 또는 첫 survey trigger 시. 		codebase-survey (Step 0.5/1/2), freshness-guard, fix-scope-expansion, pre-commit-gate (Gate 0.5)
codex CLI (OpenAI) cross-vendor 2nd opinion install/dependencies.sh 가 npm i -g @openai/codex 또는 brew install codex 시도. PATH 에서 감지.
호출 규칙은 kzk-codex-handoff SKILL.md 의 5 hard rules (stdin pipe, --ephemeral 등). 		spec-and-review (Step 2 review), large-task-delegation (plan-critic loop)
gh CLI GitHub PR / CI / 코멘트 감지만 — brew install gh 등 수동 설치. 없으면 PR 워크플로우 halt. pre-merge-sync, autonomous-boundary (PR 생성 단계)
aws-vault STS-backed AWS 자격증명 vault 감지만 — brew install aws-vault. 없으면 aws sso login 등 대체. production-access (권장만, 미설치 시 plaintext AKIA 거부)
superpowers:* 스킬 writing-plans, brainstorming, subagent-driven-development 등 외부 superpowers 플러그인 — Claude Code 가 자동 발견. 이 레포가 직접 인스톨하지 않음 (호환 의존성). spec-and-review (Step -1 brainstorming), web-loop (writing-plans + subagent-driven-development)
설계 의도: 모든 외부 의존은 graceful degradation. 도구가 없으면 해당 스킬이 fallback 경로로 떨어집니다. 예) codex CLI 없음 → OMC critic opus 로 fallback (같은 벤더라 blind spot 동일), CRG 없음 → grep fallback (transitive 정확도 ↓). install 절대 hard-fail 안 함.

6. 18개 스킬 카드

아래는 각 스킬의 frontmatter (name + version), 트리거 키워드, 핵심 메커니즘, 산출물, 연결되는 sister skill, harness-share §N 을 한 카드로 정리. 카드의 배지 의미:

entry 사용자 prompt 키워드가 1차 진입점 auto 자동 호출 (hook 또는 다른 스킬이 chain) gate commit / merge 게이트 hook 동작 일부가 hook 으로 구현됨
kzk-pre-commit-gatev1.11.0gate
모든 commit 의 게이트. 6단계 시퀀스 (Gate 0/0.5/1/1.5/1.6/2/3/4/4.5/5) 가 직렬 실행. 하나라도 FAIL → commit block. doc-only 변경 시 일부 예외.

트리거

commitpre-commitGate 0/1/1.5/2/3/4AGENTS.md syncsecrets scandoc-only

핵심 메커니즘

  • Gate 0: AGENTS.md sync + deepinit_manifest baseline 저장
  • Gate 0.5: kzk-freshness-guard 위임 (CRG reverseRefs 로 stale 메타 자동 감지)
  • Gate 1: oh-my-claudecode:ai-slop-cleaner
  • Gate 1.5: secrets grep (AKIA, ASIA)
  • Gate 1.6: production-access code-first (shell 명령 감지)
  • Gate 2/3: npm run build / npm test (scoped)
  • Gate 4: kzk-playwright-verification (UI 변경 시)
  • Gate 4.5: kzk-fix-scope-expansion (callsite cache 검증)
  • Gate 5: fresh-agent verifier (cache key = staged_diff_hash + acceptance_hash + verifier_model)

산출물

  • Gate PASS/FAIL 결정 + commit BLOCK
  • 커밋 메시지 footer: gate-PASS: 0✓ 0.5✓ 1✓ 1.5✓ 2✓ 3✓ 4✓ 4.5✓ 5✓

10. 이 문서 자동 갱신 hook — kzk-harness 전용

이 HTML 은 skills/*/SKILL.md, harness-share.md, 프로젝트 CLAUDE.md 에서 파생됩니다. 그 SoT 가 바뀌었는데 HTML 이 안 바뀌면 문서가 거짓말을 시작하니, PreToolUse hook 으로 git commit 자체를 차단합니다.

10.1 동작 방식

  • 등록 위치: .claude/settings.json (이 레포 root). repo 안에서만 동작합니다.
  • 이벤트: PreToolUse matcher Bash. 스크립트가 tool_input.command 를 보고 git commit 이 아니면 즉시 PASS.
  • git commit 인 경우: SoT 파일들(skills/**/SKILL.md + harness-share.md + CLAUDE.md) 의 정렬된 SHA-256 fingerprint 를 계산해, HTML 의 <!-- KZK_SKILL_FLOW_FINGERPRINT: ... --> 와 비교.
  • 일치 → PASS, 불일치 → {"decision":"block","reason":"..."} 로 commit 차단 + 갱신 절차 안내.

10.2 다른 사용자가 글로벌 install 해도 절대 발동 안 함

install/install-global.sh 가 쓰는 위치는 오직 ~/.claude/... 와 $HOME/.cache/kzk-harness/. 이 레포의 .claude/settings.json 과 .claude/hooks/ 는 절대 복제되지 않습니다. Claude Code 는 .claude/settings.json 을 그 디렉토리에 있을 때만 로드하므로 — 이 레포의 디렉토리에서 Claude Code 를 켰을 때만 이 hook 이 살아납니다.

10.3 SoT 가 바뀌었을 때 절차

  1. SKILL.md / harness-share.md / CLAUDE.md 수정 (예: 새 스킬 추가, 버전 bump, 트리거 키워드 변경).
  2. docs/skill-flow.html 의 본문 (해당 카드 / 표 / 다이어그램) 도 같이 수정.
  3. fingerprint 재계산: node .claude/hooks/check-skill-flow-fresh.mjs --regen. 스크립트가 새 fingerprint 를 HTML 의 주석에 in-place 갱신.
  4. 전부 staging → git commit. Hook 이 fingerprint 일치를 다시 확인하고 PASS.

10.4 응급 우회

autonomous cycle 중 hot-fix 같이 잠깐 우회할 때:

KZK_SKILL_FLOW_SKIP=1 git commit -m "..."

이 환경변수가 set 이면 hook 이 1회 PASS 합니다. 사용 시 user-queue.md 에 Q-SKILL-FLOW-STALE 로 self-기록 (사후 정리 의무).

10.5 fingerprint 알고리즘 (재현 가능)

  1. 대상 파일을 정렬 순서로 모음:
    • 모든 skills/*/SKILL.md (이름 알파벳 정렬)
    • harness-share.md
    • CLAUDE.md (이 레포의 그것)
  2. 각 파일: SHA-256(path + "\0" + content) 의 hex 추출
  3. 그 모든 hex 를 줄바꿈으로 join → 다시 SHA-256 → hex 16자 prefix 가 fingerprint

16자라서 충돌 확률은 무시 가능하지만 한 눈에 비교 가능.
