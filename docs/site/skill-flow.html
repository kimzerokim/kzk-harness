kzk-harness — Skill & Workflow Map

Single-page reference for the 18 kzk-* skills: how they call each other, where they are loaded, and which hook enforces each rule at runtime.
18 skills active 8 hooks (project + global) harness-share.md §1–§33 SoT

Single-page reference for the 18 `kzk-*` skills that compose the kzk-harness workflow layer on top of Claude Code. Documents how skills are loaded, how trigger phrases route to them, what each skill does, and how they chain in the five canonical entry-point flows.

The canonical source of truth for each skill's rules is its own skills/kzk-*/SKILL.md; cross-cutting rules that span multiple skills live in harness-share.md (§1–§33). This HTML is a read-only index derived from those two sources. When either changes, the hook described in §9 blocks git commit until this file is updated.

2. Mental model

Claude Code operates with five building blocks: the main agent, Skills (markdown), Subagents (specialist agents), Hooks (scripts), and MCP servers (external tool servers). kzk-harness layers 18 Skills + 8 Hooks on top of those primitives. It adds no new capabilities — it adds discipline: consistent, safe invocation patterns for the capabilities that already exist.

Skillmarkdown
When a trigger keyword appears in the prompt, the skill's body loads into the main context automatically. No code — the markdown text is the rulebook.

All 18 kzk-* skills follow this pattern

  • Location: ~/.claude/skills/kzk-*/SKILL.md (global) or .claude/skills/kzk-*/SKILL.md (project-only)
  • Install: install/install-global.sh or the README PROJECT-ONLY procedure
Subagentruntime
Main delegates work via Agent({ subagent_type: '...', ... }). Each subagent gets its own context window and model.

Subagent types used by this repo

  • oh-my-claudecode:explore — read-heavy exploration (sonnet)
  • oh-my-claudecode:executor — code authoring (sonnet/opus)
  • oh-my-claudecode:critic — review / validation (opus)
  • oh-my-claudecode:verifier — completion verification (fresh agent)
Hooknode mjs
Scripts bound to PreToolUse / PostToolUse / UserPromptSubmit / Stop events. They receive JSON on stdin and respond with a decision JSON or a system-reminder injection.

kzk-harness installs 8 hooks

  • install/hooks/keyword-detector.mjs and others — on global install, copied to ~/.claude/skills/.kzk-harness-shared/hooks/ and registered in ~/.claude/settings.json
  • One repo-only hook: .claude/hooks/check-skill-flow-fresh.mjs
MCP servertool
External tool servers callable by the main agent. Skills reference them by their tool names, e.g. mcp__plugin_context7_context7__query-docs.

MCP servers recommended by this repo

  • context7 — external library API docs (used in kzk-codebase-survey Step 4)
  • code-review-graph — Tree-sitter + SQLite code graph (kzk-codebase-survey Steps 0.5/1/2)
  • playwright-mcp — browser automation (kzk-playwright-verification Gate 4, kzk-web-loop)

3. Task-by-task usage guide

Each scenario below maps a concrete prompt pattern to the skills that auto-load, the main agent's role, and what to avoid. Korean trigger phrases are shown as chips because the keyword detector matches them verbatim.

1. Simple bug fix

1 file / ≤ 30 LoC / clear symptom

Good prompts

<X> 가 <Y> 로 동작 안 함. 기대: <Z>. 고쳐줘.

Auto-loaded skills

None on entry. commit trigger activates kzk-pre-commit-gate at commit time.

Main's role

Direct read + edit + commit. No subagent dispatch needed.

Avoid

Firing 버그 전수조사 or 사용성 버그 for a single-file fix — that triggers over-dispatch via R1/R2.

2. Multi-bug / regression sweep

3+ files or ambiguous symptoms

Good prompts

사용성 버그 모두 잡아줘   버그 전수조사 해줘   플랜 여러개로 쪼개고 사이클 자율로 돌면서 모두 개선

Auto-loaded skills

kzk-codebase-survey + kzk-large-task-delegation (R1 large-task fires for 버그 전수조사/사용성 버그; R2 survey-chain fires for 상세하게 봐줘/구현 확인 etc. — both routes load this skill pair)

Main's role

Direct read of 5+ files is forbidden. Delegate to EXPLORER subagent (oh-my-claudecode:explore) → synthesise results → build meta-plan → dispatch executor sonnet per cycle. Main orchestrates, verifies, and commits only.

Avoid

Main reading files directly instead of using EXPLORER. Appending 끝까지 끝내줘 without kzk-autonomous-boundary 3-slot contract first.

3. Small new feature

≤ 200 LoC, 1–2 files, clear spec

Good prompts

"<feature description>. Acceptance criteria: <AC>. Include tests."

Auto-loaded skills

None. Add TDD 로 진행 to the prompt to trigger kzk-test-coverage and superpowers:test-driven-development.

Main's role

Direct implementation. No subagent needed.

Avoid

Treating a small feature as a large task — unnecessary spec phase and codex consult add overhead.

4. Medium / large new feature

3+ files OR 200+ LoC — ORM / API / DB

Good prompts

3-phase sequence: (1) 이 기능 spec 잡자: <description> → (2) plan 작성해줘 → (3) "ok 이대로 진행" or ralph로 돌려

Auto-loaded skills

Phase 1–2: kzk-spec-and-review (includes kzk-codebase-survey Step 0 auto-precondition). Phase 3: kzk-large-task-delegation + kzk-autonomous-boundary

Main's role

Spec/plan authoring + executor result review + full 10-gate pre-commit sequence (Gate 0–5) + final commit. Spec output lands in docs/plans/<topic>-design.md.

Avoid

Skipping the spec phase for a large feature. Skipping the 3-slot autonomous contract before phase 3.

5. Architecture / design decision / DB schema / security

Good prompts

spec 잡자: <topic>. major design 이라 codex review 필수.

Auto-loaded skills

kzk-spec-and-review with mandatory codex consult (cannot be skipped for architecture topics)

Main's role

Dispatch planner opus → parallel codex consult → critic opus → synthesise frozen plan. All three roles (plan / critic / verify) use opus + xhigh effort. Code goes to executor, never main.

Avoid

Skipping codex review on security or schema decisions. Using sonnet for the planner pass on major architecture.

6. Mechanical refactoring

Rename / version bump / config flag toggle / lint follow-up / single-line change × N files (Cycle 29)

Good prompts

"[mechanical] rename X to Y across all files"

Auto-loaded skills

kzk-large-task-delegation when 3+ files are touched

Main's role

Dispatch executor with model: 'haiku' — codex consult and opus thinking are unnecessary for purely mechanical changes. Escalate to sonnet if any inference is required (variable name decisions, error message wording, conditional branching).

Avoid

Using opus for a pure rename. Using main's context directly to edit N files.

7. Implementation verification / spec audit (read-only)

Good prompts

ralph로 체크   구현 검증해줘   하나하나 확인   spec vs implementation 매칭 확인

Auto-loaded skills

R2 survey-chain (keyword-detector forced): kzk-codebase-survey + kzk-large-task-delegation

Main's role

Never read directly. Delegate to EXPLORER subagent (oh-my-claudecode:explore, model: 'sonnet' for deep reads / 'haiku' for targeted lookups). CRG MCP / CLI first, grep fallback. Output: docs/harness/surveys/YYYY-MM-DD-<topic>-verification.md.

Avoid

Main reading 5+ files directly to validate a spec. Self-declared "verification PASS" without a fresh-agent verifier.

8. Self-improvement (harness rule changes / closing meta-gaps)

Good prompts

자가개선 루프 돌려보자   harness 개선 루프   재발 방지   메타 갭 닫자

Auto-loaded skills

R7 4-skill meta-stack (keyword-detector forced): kzk-spec-and-review + kzk-large-task-delegation + kzk-pre-commit-gate + kzk-autonomous-loop

Main's role

Spec phase (codex skip only if explicitly stated with reason) → executor sonnet/haiku dispatch → main verifies + atomic commit. Apply own rules to self — main executing a large task directly is itself a meta-gap (Session-28 lesson).

Avoid

Main directly editing SKILL.md files across 3+ skills without going through executor. Skipping the spec phase for harness rule changes.

9. Autonomous mode entry (long-running / user-absent)

Good prompts

끝까지 끝내줘   자는 동안 진행   ralph로 돌려   실행해놔야 queue 보지

Auto-loaded skills

kzk-autonomous-boundary fires immediately

Main's role

ASK FIRST — get explicit answers to 3 slots before any work: (a) separate branch vs. direct commit, (b) branch name, (c) PR required or not. Silent defaults are forbidden. Direct main commits only when user explicitly says so. At context 50%: /compact <remaining tasks> with non-empty summary arg is mandatory (Q-COMPACT-EVASION halt if skipped). Before any large-task dispatch: kzk-codebase-survey required; if missing → Q-SURVEY-MISSING halt.

Avoid

Starting autonomous work before the 3-slot contract is confirmed. Running /compact without a summary argument. Dispatching a large task without a survey.

10. Commit / PR / merge

Good prompts

commit   PR 올려줘   "merge it"

Auto-loaded skills

kzk-pre-commit-gate (Gate 0–5, full 10-gate) → kzk-pre-merge-sync (deepinit + CLAUDE.md sync before PR/milestone). If commit message contains MILESTONE: / CYCLE-EXIT: / STUB-CLEAR:, or the command is gh pr create / git push origin main: Gate 6 (check-cycle-exit.mjs hook) fires and requires fresh-agent verifier with 4 sub-checks before proceeding.

Main's role

Non-doc-only full sequence: Gate 0 (AGENTS sync) → 0.5 (freshness) → 1 (ai-slop) → 1.5 (secrets AKIA/ASIA) → 1.6 (prod code-first) → 2 (build) → 3 (test) → 4 (Playwright, UI changes) → 4.5 (fix-scope) → 5 (fresh-agent verifier) → 6 (cycle-exit, if marker matched).
Doc-only fast path (*.md / docs/** only): Gate 1.5 secrets + verify-install AC2 only. Full suite runs once at cycle close.

Avoid

Skipping Gate 5 fresh-agent verifier on non-doc changes. Calling doc-only fast path when any production code is staged. Bypassing Gate 6 (KZK_CYCLE_EXIT_SKIP=1) without adding a Q-CYCLE-EXIT-STALE entry to user-queue.md.

11. Production / DB / IAM / credential

Good prompts

AWS 에 SSM 으로 접속해서 ...   production DB <X> drop (explicit user authorisation required)

Auto-loaded skills

kzk-production-access

Main's role

Even read-only access requires explicit user request — no silent production reads. State mutation: AI authors the script only; user or CI executes it. Multi-step: per-step OK sign required. STS (ASIA prefix + SessionToken) is the only temporarily-permitted credential type. Permanent AKIA keys are refused; AI provides revocation guidance instead.

Avoid

Reading production data without explicit user request. Executing state-mutating scripts directly from the AI agent.

12. UI / Playwright Gate 4 / OAuth login

Good prompts

Google 로그인 화면 떴어   로그인 버튼 (OAuth click-through starts automatically)

Auto-loaded skills

Gate 4 of kzk-pre-commit-gate auto-triggers kzk-playwright-verification when web/src/**/*.{tsx,ts,css} changes are staged.

Main's role

Dev server health pre-check (process alive + log tail error grep) before screenshots. Navigate 3+ pages, full-page screenshot, 0 console errors, 1–3 sentence narration. OAuth: agent-driven click-through — no user wait for account picker or consent. Password/MFA prompts trigger halt + user-queue entry.
6 halt entries: Q-PW-OAUTH-NEW-ACCOUNT Q-PW-OAUTH-MULTI-ACCOUNT Q-PW-OAUTH-CONSENT-LOOP Q-PW-OAUTH-STUCK Q-PW-OAUTH-CHALLENGE Q-PW-OAUTH-PROVIDER-ERROR

Avoid

Committing UI changes without Gate 4 Playwright run. Waiting for the user during OAuth when the agent can click through automatically. Skipping dev server health check (dev/prod build trap — e.g. Tailwind v4 @import order issues).

13. Autonomous + large change (multi-bug + autonomous combined)

New in v1.13.0 — combines scenario 2 (multi-bug sweep) and scenario 9 (autonomous mode)

Good prompts

끝까지 끝내줘 combined with 버그 전수조사 or 사용성 회귀 모두 잡아줘

Auto-loaded skills

kzk-autonomous-boundary (3-slot contract) + kzk-codebase-survey (pre-dispatch survey) + kzk-large-task-delegation (executor sonnet dispatch)

Main's role

  1. 3-slot ASK FIRST: destination / branch name / PR
  2. EXPLORER subagent runs kzk-codebase-survey — mandatory before any multi-file autonomous dispatch
  3. Survey result + frozen plan included when dispatching executor sonnet
  4. Each cycle ends with kzk-pre-commit-gate Gate 0–5 + atomic commit
  5. At context 50%: /compact <remaining tasks> with summary arg (Q-COMPACT-EVASION prevention)

Avoid

Dispatching executor without prior survey → Q-SURVEY-MISSING. Main reading 5+ files directly → Q-MAIN-DIRECT-EDIT.

Meta rules (all tasks)

  1. Branch contract — ASK FIRST 3-slot before any autonomous or multi-commit task. New branch is the default unless user explicitly says otherwise.
  2. 5+ file read = main forbidden — always delegate to EXPLORER subagent (read-heavy audit dispatch shape).
  3. 3+ file edit OR 200+ LoC = executor delegation — main orchestrates + verifies + commits only. Direct execution is the Session-6/Session-28 anti-pattern.
  4. Session-scoped contract — re-confirm only when scope changes materially (doc-only → code, single-module → multi-module, low-risk → destructive).
  5. Doc-only fast path — *.md / docs/**-only commits: Gate 1.5 + AC2 only. Full suite once at cycle close (Cycle 29).
  6. Scope estimation (Cycle 30) — non-trivial requests: 30-second estimate via git status + dir scan + CRG → 1-line preamble [scope] est. N files / M LoC → <route> → proceed with that routing. If estimate is exceeded mid-execution (5+ file reads or 3+ file edits), halt immediately and restart via delegation.
  7. TDD sequence (Cycle 30) — all new features and bug fixes in autonomous mode or large-task dispatch: failing test first (red) → impl (green) → refactor → commit. Bug fix without a regression test = incomplete.
  8. /compact arg mandatory (Cycle 54) — at context 50% in autonomous mode, /compact <remaining tasks> with a non-empty summary is required. Empty /compact triggers Q-COMPACT-EVASION halt.

Model / thinking-level summary (Cycle 29–30)

TierUse
Opus + xhighPlan authoring (default), critic on architecture/security, semantic verify, ambiguous spec
Opus + highWell-scoped plan, mechanical critic (≤ 200 LoC, no security), pre-spec'd verify
SonnetGeneral implementation (executor), mechanical verify (build/test/screenshot), explorer deep read
HaikuVersion bump, frontmatter rewrite, single-line config, lint follow-up, progress log append, atomic rename, explorer targeted lookup, simple git ops (status/log/diff/commit -m/fast-forward merge/non-conflict cherry-pick)

Target distribution: 50% sonnet + 30% haiku + 20% opus. Omitting model parameter defaults to opus — cost explosion, strictly forbidden.

Trigger gaps (currently unmatched phrases)

  • "<X> 만들어줘" (simple new feature) — intentional: simple tasks handled by main directly
  • "성능 개선" / "perf" — no performance audit trigger (candidate for a future cycle)
  • "보안 감사" / "security review" — partially covered by kzk-production-access; no dedicated audit trigger

To close a gap: trigger 자가개선 루프 → extends install/hooks/keyword-detector.mjs RULES.

6. 18 skill cards

Each card summarizes the skill's name + version, trigger keywords, core mechanism, outputs, linked sister skills, and harness-share §N reference. Badge meanings:

entry User prompt keyword is the primary entry point auto Auto-invoked (by a hook or chained from another skill) gate commit / merge gate hook Part of the enforcement is implemented as a hook
kzk-pre-commit-gatev1.12.0gate
The gate for every commit. Ten gate levels (0 / 0.5 / 1 / 1.5 / 1.6 / 2 / 3 / 4 / 4.5 / 5) run in strict sequence. Any single FAIL blocks the commit. Doc-only changes bypass some levels.

Triggers

commitpre-commitGate 0/1/1.5/2/3/4AGENTS.md syncsecrets scandoc-only

Core mechanism

  • Gate 0: AGENTS.md sync + deepinit_manifest baseline snapshot
  • Gate 0.5: delegates to kzk-freshness-guard (CRG reverseRefs detects stale meta docs automatically)
  • Gate 1: oh-my-claudecode:ai-slop-cleaner
  • Gate 1.5: secrets grep (AKIA, ASIA)

Key details

  • Global (default propagate): ~/.claude/skills/.kzk-harness-shared/hooks/check-cycle-exit.mjs
