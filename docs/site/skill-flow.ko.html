kzk-harness — 스킬 & 워크플로우 지도

18개 kzk-* 스킬의 단일 페이지 레퍼런스: 스킬 간 호출 관계, 로딩 위치, 각 규칙을 런타임에 강제하는 훅을 한 곳에서 확인할 수 있습니다.
18개 스킬 활성 8개 훅 (프로젝트 + 글로벌) harness-share.md §1–§33 SoT

이 페이지의 영어판: skill-flow.html

Claude Code 위에 얹는 kzk-harness 워크플로우 레이어의 18개 kzk-* 스킬을 한 페이지로 정리. 스킬이 어떻게 로드되는지, 어떤 트리거 문구가 어떤 스킬을 부르는지, 각 스킬이 무엇을 하는지, 5가지 진입점 플로우에서 서로 어떻게 연결되는지 보여줍니다.

각 스킬 규칙의 정식 소스는 해당 스킬의 skills/kzk-*/SKILL.md, 여러 스킬에 걸친 공통 규칙은 harness-share.md (§1–§33). 이 HTML 은 두 소스에서 파생된 읽기 전용 인덱스 — §9 의 훅이 동기화를 강제합니다.

2. 멘탈 모델

Claude Code는 5가지 구성 요소로 작동합니다: 메인 에이전트, 스킬(마크다운), 서브에이전트(전문 에이전트), 훅(스크립트), MCP 서버(외부 툴 서버). kzk-harness는 이 기본 요소 위에 18개 스킬 + 8개 훅을 추가합니다. 새로운 기능을 추가하는 것이 아니라 규율을 추가합니다: 기존 기능의 일관되고 안전한 호출 패턴.

Skillmarkdown
프롬프트에 트리거 키워드가 나타나면 스킬 본문이 메인 컨텍스트에 자동으로 로드됩니다. 코드가 없습니다 — 마크다운 텍스트 자체가 규칙서입니다.

18개 kzk-* 스킬 모두 이 패턴을 따름

  • 위치: ~/.claude/skills/kzk-*/SKILL.md (글로벌) 또는 .claude/skills/kzk-*/SKILL.md (프로젝트 전용)
  • 설치: install/install-global.sh 또는 README PROJECT-ONLY 절차
Subagentruntime
메인은 Agent({ subagent_type: '...', ... })를 통해 작업을 위임합니다. 각 서브에이전트는 독립적인 컨텍스트 창과 모델을 가집니다.

이 레포에서 사용하는 서브에이전트 유형

  • oh-my-claudecode:explore — 대량 읽기 탐색 (sonnet)
  • oh-my-claudecode:executor — 코드 작성 (sonnet/opus)
  • oh-my-claudecode:critic — 리뷰 / 검증 (opus)
  • oh-my-claudecode:verifier — 완료 검증 (fresh agent)
Hooknode mjs
PreToolUse / PostToolUse / UserPromptSubmit / Stop 이벤트에 바인딩된 스크립트입니다. stdin으로 JSON을 받아 결정 JSON 또는 system-reminder 주입으로 응답합니다.

kzk-harness가 설치하는 8개 훅

  • install/hooks/keyword-detector.mjs 등 — 글로벌 설치 시 ~/.claude/skills/.kzk-harness-shared/hooks/에 복사되고 ~/.claude/settings.json에 등록됨
  • 레포 전용 훅: .claude/hooks/check-skill-flow-fresh.mjs
MCP servertool
메인 에이전트가 호출 가능한 외부 툴 서버입니다. 스킬은 툴 이름으로 참조합니다 (예: mcp__plugin_context7_context7__query-docs).

이 레포에서 권장하는 MCP 서버

  • context7 — 외부 라이브러리 API 문서 (kzk-codebase-survey Step 4에서 사용)
  • code-review-graph — Tree-sitter + SQLite 코드 그래프 (kzk-codebase-survey Steps 0.5/1/2)
  • playwright-mcp — 브라우저 자동화 (kzk-playwright-verification Gate 4, kzk-web-loop)

3. 작업 유형별 가이드

각 시나리오는 구체적인 prompt 패턴 → 자동 로드 스킬 → 메인 역할 → 피해야 할 것을 매핑합니다. 한국어 트리거 phrase 는 키워드 감지기가 그대로 매칭하므로 chip 형식으로 표시합니다.

1. 단순 버그 픽스

1 파일 / ≤ 30 LoC / 명확한 증상

좋은 prompt

<X> 가 <Y> 로 동작 안 함. 기대: <Z>. 고쳐줘.

자동 로드

없음 (메인 직접 처리). 커밋 시 commit 발화로 kzk-pre-commit-gate 자동 활성.

메인 역할

직접 read + edit + commit. 서브에이전트 dispatch 불필요.

피하기

단일 버그에 버그 전수조사 / 사용성 버그 같은 large-task trigger 발화 → over-dispatch.

2. 다중 버그 / 사용성 회귀 sweep

3+ 파일 또는 모호한 증상

좋은 prompt

사용성 버그 모두 잡아줘   버그 전수조사 해줘   플랜 여러개로 쪼개고 사이클 자율로 돌면서 모두 개선

자동 로드

kzk-codebase-survey + kzk-large-task-delegation (R2 chain rule)

메인 역할

5+ 파일 직접 read 금지. EXPLORER subagent (oh-my-claudecode:explore) 위임 → 결과 합성 → 메타 plan → executor sonnet 위임 cycle 반복. 메인은 orchestrate + verify + commit 만.

피하기

메인이 EXPLORER 대신 직접 파일 read. 끝까지 끝내줘 추가 시 kzk-autonomous-boundary 3-슬롯 contract 확인 없이 진입.

4. 중·대형 신기능

3+ 파일 또는 200+ LoC — ORM / API / DB 영역

좋은 prompt

권장 3-phase 시퀀스: (1) 이 기능 spec 잡자: <description> → (2) plan 작성해줘 → (3) "ok 이대로 진행" 또는 ralph로 돌려

자동 로드

Phase 1–2: kzk-spec-and-review (Step 0 kzk-codebase-survey 자동 선행 포함). Phase 3: kzk-large-task-delegation + kzk-autonomous-boundary

메인 역할

spec/plan 작성 + executor 결과 review + Pre-commit Gate 0–5 (전체 10-gate) + 최종 commit. spec 산출물: docs/plans/<topic>-design.md.

피하기

대형 기능에 spec phase 건너뛰기. Phase 3 진입 전 3-슬롯 autonomous contract 확인 생략.

5. 아키텍처 / 설계 결정 / DB schema / 보안

좋은 prompt

spec 잡자: <topic>. major design 이라 codex review 필수.

자동 로드

kzk-spec-and-review (codex consult 필수 — 아키텍처 주제에서 생략 불가)

메인 역할

planner opus dispatch → codex CLI 병렬 consult → critic opus → 합성된 frozen plan. plan / critic / verify 모두 opus + xhigh effort. 코드는 executor 위임, 메인 직접 금지.

피하기

보안·schema 결정에 codex review 생략. major architecture 에 sonnet planner 사용.

6. 메커니컬 리팩토링 (Cycle 29 신규 haiku tier)

좋은 prompt

ralph로 체크   구현 검증해줘   하나하나 확인   spec vs implementation 매칭 확인

자동 로드

R2 chain: kzk-codebase-survey + kzk-large-task-delegation

메인 역할

절대 직접 read 금지. EXPLORER subagent 위임 (oh-my-claudecode:explore, model: 'sonnet' 깊은 read / 'haiku' 타겟 lookup). CRG MCP / CLI 우선, grep fallback. 출력: docs/harness/surveys/YYYY-MM-DD-<topic>-verification.md.

8. 자가개선 (harness 룰 변경 / 메타 갭 닫기)

좋은 prompt

자가개선 루프 돌려보자   harness 개선 루프   재발 방지   메타 갭 닫자

자동 로드

R5 4-set 메타 스택: kzk-spec-and-review + kzk-large-task-delegation + kzk-pre-commit-gate + kzk-autonomous-loop

메인 역할

spec phase (codex skip 시 명시 + 사유 필수) → executor sonnet/haiku dispatch → 메인 검증 + atomic commit. 자기 자신에게 룰 적용 의무 — 메인이 직접 large-task 실행하면 그 자체가 메타 갭 (Session-28 lesson).

피하기

메인이 3+ 스킬 SKILL.md 파일을 executor 없이 직접 edit. harness 룰 변경에 spec phase 건너뛰기.

9. 자율 모드 진입 (장시간 / 사용자 부재)

좋은 prompt

끝까지 끝내줘   자는 동안 진행   ralph로 돌려   실행해놔야 queue 보지

자동 로드

kzk-autonomous-boundary 즉시 발동

메인 역할 (필수)

진입 전 ASK FIRST — 3-슬롯 명시 답 받기: (a) 별 branch vs 직접 commit (b) branch 이름 (c) PR 여부. silent default 금지. 직접 main commit 은 사용자 명시 인가 시만 허용. context 50% 도달 시: /compact <remaining tasks> + 비어있지 않은 요약 인자 필수 (Q-COMPACT-EVASION halt 방지). 대용량 변경 dispatch 전: kzk-codebase-survey 필수; 없으면 → Q-SURVEY-MISSING halt.

피하기

3-슬롯 contract 확인 전 자율 작업 시작. 요약 인자 없이 /compact 실행. survey 없이 large-task dispatch.

10. commit / PR / merge

좋은 prompt

commit   PR 올려줘   "merge it"

자동 로드

kzk-pre-commit-gate (Gate 0–5, 전체 10-gate) → kzk-pre-merge-sync (PR/milestone 직전 deepinit + CLAUDE.md sync)

메인 역할

doc-only 아닌 일반 commit: Gate 0 (AGENTS sync) → 0.5 (freshness) → 1 (ai-slop) → 1.5 (secrets AKIA/ASIA) → 1.6 (prod code-first) → 2 (build) → 3 (test) → 4 (Playwright, UI 변경 시) → 4.5 (fix-scope) → 5 (fresh-agent verifier).
doc-only 빠른 길 (*.md / docs/** 단독): Gate 1.5 secrets + verify-install AC2 만. full suite 는 cycle close 1회.

피하기

doc-only 아닌 변경에 Gate 5 fresh-agent verifier 생략. production 코드 staged 상태에서 doc-only 빠른 길 사용.

13. 자율 모드 + 대용량 변경 (autonomous + multi-file)

v1.13.0 신규 — 시나리오 2 (다중 버그) + 시나리오 9 (자율 모드) 결합

좋은 prompt

끝까지 끝내줘 + 버그 전수조사 / 사용성 회귀 모두 잡아줘 조합

자동 로드

kzk-autonomous-boundary (3-슬롯 contract) + kzk-codebase-survey (pre-dispatch survey 필수) + kzk-large-task-delegation (executor sonnet dispatch)

메인 역할

  1. branch contract 3-슬롯 ASK FIRST (destination / branch name / PR 여부)
  2. EXPLORER subagent 로 kzk-codebase-survey 선행 — autonomous 모드에서 multi-file scope 의 large-task dispatch 직전 필수
  3. survey 결과 + frozen plan 포함하여 executor sonnet dispatch
  4. 각 cycle 끝 kzk-pre-commit-gate Gate 0–5 + atomic commit
  5. context 50% 도달 시 /compact <remaining tasks> 인자 필수 (Q-COMPACT-EVASION 방지)

피하기

survey 없이 executor dispatch → Q-SURVEY-MISSING. 메인이 5+ 파일 직접 read → Q-MAIN-DIRECT-EDIT.

메타 룰 (모든 작업 공통)

  1. Branch contract — autonomous 또는 multi-commit 작업 시 시작 전 ASK FIRST 3-슬롯. 사용자 명시 외엔 새 branch 가 default.
  2. 5+ file read = 메인 금지 — 무조건 EXPLORER subagent 위임 (read-heavy audit dispatch shape).
  3. 3+ file edit OR 200+ LoC = executor 위임 — 메인은 orchestrate + verify + commit. 직접 실행하면 Session-6/Session-28 anti-pattern.
  4. Session 단위 contract 고정 — scope 가 material 하게 바뀔 때만 재확인 (doc-only → code, single-module → multi-module, low-risk → destructive).
  5. doc-only 빠른 길 — *.md / docs/** 단독 commit 은 Gate 1.5 + AC2 만, full suite 는 cycle close 1회 (Cycle 29 fast path).
  6. Scope estimation (Cycle 30 신규) — non-trivial 요청은 git status + 디렉토리 scan + CRG 로 30초 추정 → 1-line preamble [scope] est. N files / M LoC → <route> → 그 라우팅으로 진행. 추정 빗나가면 (mid-execution 5+ 파일 read 또는 3+ 파일 edit) 즉시 halt + restart 위임.
  7. TDD sequence (Cycle 30 신규) — autonomous 모드 또는 large-task dispatch 의 모든 신기능/버그픽스: 실패 test 먼저 (red) → impl (green) → refactor → commit. 버그픽스 = 회귀 test 가 first artifact, 없으면 incomplete.
  8. /compact 인자 의무 (Cycle 54 신규) — autonomous 모드 내 context 50% 도달 시 반드시 /compact <remaining tasks> 형태로 호출. 빈 /compact 는 Q-COMPACT-EVASION halt 발동.

모델 / thinking-level 요약 (Cycle 29–30)

Tier사용
Opus + xhighplan authoring (default), critic on architecture/security, semantic verify, ambiguous spec
Opus + highwell-scoped plan, mechanical critic (≤ 200 LoC, no security), pre-spec'd verify
Sonnet일반 implementation (executor), mechanical verify (build/test/screenshot), explorer 깊은 read
Haikuversion bump, frontmatter rewrite, single-line config, lint follow-up, progress log append, atomic rename, explorer 타겟 lookup, git ops 단순 (status/log/diff/commit -m/fast-forward merge/non-conflict cherry-pick)

목표 분포: 50% sonnet + 30% haiku + 20% opus. model 파라미터 명시 누락 = opus default = 비용 폭증, 절대 금지.

트리거 갭 (현재 매칭 안 되는 흔한 phrase)
